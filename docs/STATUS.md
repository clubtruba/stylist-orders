# Состояние реализации

Обновлено 11.11.2026.

## Реализовано и проверено локально
- Отдельная модель заказа со стилистом, получателем и снимком адреса.
- Сохраненные получатели с адресами в России; проверка имени латиницей, индекса и телефона.
- Несколько заказов и сохранение очереди ссылок при переключении и перезапуске.
- Три действия в боте: отложить, расчет и завершение формирования.
- Получение курса ЦБ с кэшем по московской дате; хранение фактической даты действия курса.
- Неизменяемые расчеты и доплата только за новые позиции.
- Подтверждение скриншотом конкретного расчета; запись Telegram message ID против повторов.
- Сохранение изображений на сервере; доступ к ним по проверенным правам.
- Отмена позиций или заказа, суммы возврата из оплаченного расчета, отдельное подтверждение возврата денег.
- Уведомления стилисту и подключенному получателю через outbox.
- Одноразовые приглашения получателя: без права оформления или доступа к Mini App.
- Mini App: заказы, получатели, товары, расчеты, скриншоты, возвраты и стоимость доставки.
- Прежние административные экраны покупок, склада, адресов и отправлений сохранены отдельным разделом.
- Отдельные настройки разрешенных Telegram ID применяются ботом и API.
- 68 тест проходит, включая PostgreSQL, API, платежи и сценарий переключения заказов бота.
- Сборка Mini App проходит; обновлены зависимости, npm audit не находит известных проблем.
- Локальная сборка Docker-образа API проходит.
- Проверены мобильный экран 390px и раздел администрирования на демонстрационных данных в отдельной локальной базе.

## Ограничения и следующие проверки
- Четыре присланные карточки Zara/H&M возвращают HTTP 403 и локально, и с сервера. Первый запуск использует ручное подтверждение/ввод цены. Автоматический разбор реализован для доступного Product JSON-LD, но на живых карточках этих магазинов не подтвержден.
- Реальные Telegram-сценарии двумя аккаунтами еще не проверены.
- API и PostgreSQL уже работают отдельно на сервере. Резервное восстановление прошло, ежедневная копия установлена через пользовательский cron. HTTPS10000 включен пользователем, Pages опубликован, бот запущен.
- Сумма возврата хранится по полной позиции; возврат части количества одной позиции не входит в текущий интерфейс.

Скриншот docs/screenshots/order-mobile.png показывает вымышленный пример в локальной тестовой базе.

Серверные проверки: health нового API — 200; без подписи — 401; три разрешенных оператора — 200 с ожидаемыми ролями; посторонний ID — 403. Старый API также отвечает.

## Проверено после запуска
- Новый и прежний API доступны снаружи по HTTPS с проверкой сертификата.
- Tailscale10000 ведет к новому localhost:8011; Tailscale443 сохранил старый localhost:8000.
- Xray на 8443 сохранен; ответы 16 контрольных HTTP-адресов совпадают с проверкой до изменения.
- style.papamio.es опубликован, сертификат approved, обязательный HTTPS включен.
- Сборка сайта содержит правильный адрес нового API; CORS разрешает origin style.papamio.es.
- Новый bot-контейнер работает без перезапусков, есть активное HTTPS-соединение; конфликтующий webhook отсутствует.
- В Telegram проверены команды start/new/orders и кнопка «Заказы» с правильным URL.
- После запуска создана новая резервная копия на двух дисках и повторно успешно проверено восстановление.

Живую приемку создания заказа и отправки скриншота должен выполнить пользователь через разрешенный Telegram-аккаунт по TESTING.md. Успешный запуск контейнера не заменяет эту проверку.

Форма получателя обновлена: пошаговый ввод, необязательный Telegram username, навигация назад/отмена и сохранение прогресса. Проверены пропуск поля, пустой API-ввод, неверный ник, валидация на каждом шаге и возобновление формы после чтения из базы.
