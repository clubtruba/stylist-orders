# Архитектура и данные

Бот и Mini App обращаются к одной серверной бизнес-логике. База PostgreSQL — источник данных. GitHub Pages содержит только публичные статические ресурсы. Токен Telegram, ключи и платежные вложения находятся на сервере.

## Планируемые сущности
- users: Telegram ID, роль, активность; отдельная запись для тестового аккаунта.
- customers: имя, телефон, username; история заказов.
- addresses: страна, адрес, индекс; снимок адреса в заказе, чтобы редактирование клиента не меняло старую отправку.
- orders: публичный номер, стилист, получатель, стадия оформления, стадия исполнения, версия, даты.
- order_items: ссылка, магазин, название, размер, цвет, количество, цена EUR, источник цены, дата проверки, доступность.
- exchange_rates: валюта, номинал, значение за единицу, дата действия, время загрузки, источник.
- quotes / quote_items: неизменяемый снимок товаров, курса, надбавок и округленного результата.
- payment_attachments: заказ, клиент, расчет, Telegram file_id, сохраненный файл, время; без распознавания содержимого.
- payments: сумма, валюта, ручное подтверждение, подтвердивший пользователь; отдельно от вложений.
- shipments: перевозчик, трек-номер, ссылка отслеживания, дата отправки.
- order_events: история действий и статусов, автор, время.
- recipient_invites: одноразовый код привязки Telegram к получателю, срок действия.
- notification_outbox: адресат, событие, состояние доставки, попытки.
- processed_updates: защита от повторной обработки Telegram updates.

## Состояния
Оформление и исполнение имеют разные поля. Оформление: draft → awaiting_payment_attachment → draft либо submitted в зависимости от действия стилиста. Submitted не открывается повторно, но допускает отмены и возвраты. Исполнение использует прежние статусы товаров. Получение скриншота подтверждает оплату конкретного расчета без ручной проверки. Курс и суммы берутся из неизменяемого расчета; дата скриншота хранится отдельно. Уже оплаченные позиции не переоцениваются при дополнении заказа. Рублевая сумма распределяется по позициям с точным сохранением итоговой суммы; возврат использует эти сохраненные доли.

## Надежность
Транзакции для изменения заказа и записи уведомлений; блокировка/версия для одновременного редактирования. Проверка владельца заказа на сервере. Вложения хранятся вне публичного сайта и включаются в резервные копии. Минимизация персональных данных в журналах. Настраиваемые лимиты файлов и проверка формата загрузок. Получение товаров по URL требует ограничений адресов и защиты от запросов во внутреннюю сеть.
