# Подготовка развертывания

## Изоляция
- Репозиторий: https://github.com/clubtruba/stylist-orders.
- Серверная папка: /mnt/ai/repos/stylist-orders, рядом с telegram-orders.
- Серверные настройки: /mnt/ai/compose/stylist-orders/.env.
- Данные: /mnt/ai/data/stylist-orders, PostgreSQL и payment-proofs.
- Compose project: stylist-orders; сеть stylist-orders-network.
- API слушает только 127.0.0.1:8011. PostgreSQL не публикует порт.
- Старый проект и маршрут HTTPS на порту 443 не заменяются.

## Новый HTTPS-вход
Планируется отдельный Funnel HTTPS-порт 10000 к новому API на localhost:8011:

```sh
tailscale funnel --bg --https=10000 http://127.0.0.1:8011
```

Будущий URL API: https://alex-server.tail684c35.ts.net:10000/api/v1.

Это добавление нового публичного входа в общую конфигурацию Tailscale. До применения нужно отдельно подтвердить изменение: в документах предыдущего сервера запрещалось менять Tailscale без согласованного шага. Не применять reset или замену маршрута 443. Перед и после проверить tailscale serve status и доступность старого API.

## Порядок запуска
1. Проверить диски /mnt/ai и /mnt/archive_hdd_serv, свободный localhost-порт 8011 и сохраненный статус старого стека.
2. Разместить новый код и отдельное окружение с фактическими значениями.
3. Проверить Compose config без вывода секретов, собрать новые образы.
4. Запустить только новую базу, миграцию и API. Проверить localhost:8011/api/v1/health (service=stylist-orders).
5. Сделать резервную копию и пробное восстановление в отдельную временную базу.
6. После подтверждения добавить HTTPS-вход 10000, проверить новый и прежний API.
7. Установить VITE_API_BASE_URL в новом репозитории и вручную запустить Deploy Stylist Mini App. Workflow откажется публиковать сайт до успешной проверки нового API.
8. Проверить style.papamio.es, сертификат, CORS, запрос без подписи и вход разрешенными аккаунтами.
9. Запустить новый бот и установить кнопку Mini App. Проверить сценарий с тестовым аккаунтом, затем со стилистом.
10. Проверить отдельную задачу резервного копирования cron и следующее срабатывание.

## Откат
Остановить только Compose-проект stylist-orders. При необходимости выключить только Funnel-порт 10000. Старую базу, сеть, API и маршрут 443 не изменять. Новые данные и резервные копии сохраняются. Не выполнять compose down -v.

## Резервные копии
Скрипты backup.sh и restore-drill.sh сохраняют базу и платежные изображения на два отдельных диска. Пока автоматическое удаление старых копий не включено. Нужно контролировать объем дисков и согласовать срок хранения после пробного запуска.

## Права на добавление HTTPS-входа
Пользователь явно разрешил новый Tailscale-вход на порту 10000. Повторная проверка: порт свободен по IPv4/IPv6, оба локальных API работают. Выполнение команды от muka1532 отклонено Tailscale: требуется sudo. Выполнение с sudo без пароля также недоступно. Конфигурация не изменилась; старый маршрут 443 сохранен. Пользователь должен выполнить согласованную sudo-команду в интерактивном SSH-сеансе; расширение постоянных прав оператора Tailscale не требуется.
