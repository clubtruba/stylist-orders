# Требования проекта

Состояние: обновлено 11.11.2026. Получены ответы на вопросы 1–9 и уточнение о сохранении выставленной суммы.

## Назначение
Telegram-бот, серверная часть и Telegram Mini App для заказов вещей из магазинов Испании. Администратор покупает и отправляет товары; стилист формирует заказы для получателей. Дополнительный разрешенный аккаунт используется для проверки.

## Границы проекта
Это новый отдельный проект в папке `HomeLab Server/stylist-orders`, созданный на базе предыдущего бота. Предыдущий проект не изменяется. Все новые документы и исходники сохраняются в новой папке. Новый бот, база данных и развертывание должны быть отделены от предыдущего проекта.

## Подтвержденные требования
- Доступ только для разрешенных Telegram ID, роли администратора и стилиста.
- Получатель: имя латиницей как в паспорте, полный адрес, индекс, телефон, Telegram username.
- Несколько параллельных заказов; сохранение черновиков и возобновление по номеру заказа.
- Добавление товаров ссылками. Кнопки: «Продолжить позже», «Расчет», «Завершить заказ».
- Приоритетные магазины: Zara (zara.com) и H&M Испания (www2.hm.com/es_es). Предпочтительно получать данные товара и цену автоматически по ссылке. Если это не удалось, допускается ручной ввод цены. Размер, цвет и количество вводятся вручную.
- При повторном расчете показываются общая стоимость заказа и отдельно сумма доплаты с учетом предыдущей оплаты.
- «Продолжить позже» сохраняет заказ и позволяет создать другой.
- «Расчет» сохраняет расчет, запрашивает скриншот оплаты, после получения позволяет переключиться на другой заказ. Текущий заказ допускает дополнение.
- «Завершить заказ» запрашивает расчет и скриншот, после чего формирование заказа закончено. Исполнение и доставка отслеживаются отдельно.
- Скриншоты не распознаются, сохраняются как вложения конкретного клиента и заказа.
- Прикрепления скриншота достаточно для подтверждения оплаты; ручное подтверждение администратором не требуется. Повторная обработка того же сообщения не должна создавать вторую оплату.
- После завершения формирования заказ не открывается повторно. Администратор может отменить весь заказ или отдельные позиции, в том числе из-за отсутствия товара или размера.
- Возврат оформляется по отдельным позициям либо всему заказу. Возвращаемая сумма в RUB определяется сохраненной стоимостью оплаченных позиций из выставленного расчета. Дата скриншота фиксирует оплату, но не меняет курс или сумму расчета. Неоплаченные отмененные позиции не создают денежного возврата.
- Если скриншот прикреплен позже даты расчета, сохраняется выставленная сумма. Новые позиции рассчитываются отдельно по актуальному курсу; уже оплаченные позиции не переоцениваются.
- Доставка оплачивается отдельно и не входит в расчет товаров. Администратор может внести стоимость доставки после отправки; она отображается отдельно.
- Сохраняются прежние статусы товаров, отмены и возвраты. Доступны действия для отдельных позиций и всего заказа с сохранением истории.
- Страна доставки всегда Россия. При новом заказе можно выбрать сохраненного клиента и его адрес.
- Интерфейс на русском; даты и время бизнес-операций определяются по Europe/Moscow. Источник курса — ЦБ РФ.
- Стоимость в EUR = сумма товаров × 1,20. Стоимость в RUB = стоимость EUR × курс ЦБ РФ × 1,05.
- Курс хранится с датой действия; нельзя незаметно подставлять устаревший курс. Выходные и праздники требуют правил использования действующего курса ЦБ.
- Администратор видит черновики, оформленные заказы и данные для отправки.
- Изменения статуса и трек-номер отправляются стилисту; получателю — после регистрации у бота.
- База сохраняет клиентов, товары, расчеты, платежи, статусы для аналитики.
- Сервер пользователя обслуживает API и бота. Статическое приложение размещается на GitHub Pages с новым поддоменом.
- Сервер и способ доступа те же, что у предыдущего проекта. Новый репозиторий: https://github.com/clubtruba/stylist-orders. Новый проект располагается в отдельной соседней папке на сервере; его база, файлы и процессы изолированы. Старый бот и публикация продолжают работать независимо.

## Предварительные технические решения
Денежные суммы вычисляются десятичной арифметикой с округлением до копеек/центов. Каждый расчет сохраняет снимок цен, курса и коэффициентов. Подтвержденная скриншотом оплата распределяется по конкретным позициям; сохраняются дата оплаты и рублевые суммы для воспроизводимого возврата. Возврат имеет собственное состояние: оформление возврата не означает, что деньги уже возвращены. Сервер проверяет Telegram Mini App initData и роль при каждом запросе; frontend не содержит токен бота. Для получателей предусматривается персональная ссылка запуска бота с непрозрачным одноразовым кодом.
